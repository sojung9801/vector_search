# 단일 영상 로컬 멀티모달 검색 앱 기획서

작업명: **영상찾기**

## 1. 문서 목적

한 개의 영상을 사용자의 Mac에서 분석하고, 자연어로 영상 속 **발화 내용과 화면 장면**을 검색하는 앱의 제품 범위와 완료 기준을 정의한다.

이 문서는 무엇을 만들지 결정하는 기획서다. 구체적인 구현 순서와 기술 선택은 `02-development-plan.md`에서 다룬다.

## 2. 제품 한 줄 정의

> 사용자가 로컬 영상 한 개를 선택하고 자연어로 질문하면, 관련 장면을 찾아 해당 타임코드부터 재생해 주는 완전 로컬 검색 앱.

## 3. 프로젝트 전제

- 한 번에 검색하는 활성 영상은 한 개다.
- 사용자는 활성 영상을 다른 로컬 영상으로 교체할 수 있다.
- 분석이 완료된 이전 영상의 색인은 보관한다.
- 이전 영상을 다시 선택하면 원본이 변경되지 않은 경우 기존 색인을 재사용한다.
- 여러 영상에 걸친 통합 검색은 제공하지 않는다.
- 새로 선택한 파일의 SHA-256이 기존 영상과 같으면 중복 영상임을 알리고 사용자 선택을 받는다.
- 앱과 AI 모델은 Apple Silicon Mac에서 로컬로 실행한다.
- 원본 영상, 자막, 프레임, 임베딩은 외부 서버로 전송하지 않는다.
- Gemini, OpenAI 등 외부 AI API는 사용하지 않으며 API 사용료가 발생하지 않아야 한다.
- 검색어는 한국어·영어·일본어를 모두 지원한다.
- 질의 언어와 영상 속 발화 언어가 달라도 검색하는 교차언어 검색을 지원한다.
- 약 1시간 분량 영상은 5분 이내에 기본 검색 가능 상태가 되는 것을 목표로 한다.
- OCR·화자 구분·번역·정밀 장면 분석은 검색 가능 상태 이후 백그라운드에서 보강할 수 있다.
- 최대 10시간 길이의 영상을 지원한다.
- 10시간 영상은 5분 이내 부분 검색을 시작하고, 1시간 이내에 전체 시간 범위의 기본 검색을 제공하는 것을 목표로 한다.
- 분석 중에는 앱이 실행되어 있고 Mac이 깨어 있는 것을 전제로 한다.
- 브라우저 창을 닫아도 로컬 백엔드가 실행 중이면 분석을 계속한다.
- 앱이 종료되면 진행 상태를 저장하고 다음 실행에서 이어서 처리한다.
- 동일 원본 영상의 공통 데이터와 모든 분석 버전을 합친 파생 데이터 용량은 최대 2GB로 제한한다.
- AI 모델 캐시는 영상별 색인 제한과 분리하며 약 4~8GB 사용을 허용한다.
- 최초 실행 시 모델의 예상 다운로드 용량과 기본 저장 위치를 보여주고 사용자 확인 후 자동 다운로드한다.
- 완료된 모델 설치 뒤에는 색인과 검색에 네트워크 연결이 필요하지 않다.
- 원본 영상은 복사하지 않으며 색인 용량에 포함하지 않는다.
- 초기 검증 장비는 Apple M3, 통합 메모리 16GB, arm64, macOS 26.3이다.
- 현재 데이터 볼륨 여유 공간은 약 114GiB이며 개발 중에도 모델·색인·임시 파일을 합친 여유 공간을 사전 검사한다.
- 초기 버전은 소유자의 Mac 한 대에서만 사용하는 개인용 앱이다.
- 현재 목적은 개인 실험이며 상용 배포를 전제로 하지 않는다.
- 다만 향후 상용화 가능성을 고려해, 성능이 비슷하면 상업 이용 가능한 라이선스의 라이브러리와 모델을 우선 선택한다.
- 비상업·연구 전용 또는 별도 조건이 있는 모델을 실험에 사용할 수는 있지만, UI와 문서에 해당 제한 및 상용 대체 후보를 명시한다.
- 다른 사용자에게 배포하기 위한 설치 패키지, 계정, 권한 관리는 범위에서 제외한다.
- 초기 UI는 브라우저에서 실행하는 로컬 웹 앱으로 제공한다.
- 사용자는 터미널 명령 없이 macOS 앱 아이콘을 더블클릭해 실행한다.
- 로컬 실행용 `.app`이 백엔드를 시작하고 준비가 끝나면 기본 브라우저에서 웹 UI를 연다.
- 실행 중에는 macOS 메뉴 막대 아이콘을 표시하고 검색 화면 열기, 분석 상태 확인, 앱 종료 기능을 제공한다.
- FFmpeg, Python 런타임과 필수 코드 패키지는 앱에 포함하며 사용자가 Homebrew나 Python을 따로 설치하지 않는다.
- 용량이 큰 AI 모델 파일은 앱 번들과 분리하고 최초 실행 설정에서 내려받는다.
- 네이티브 Mac 앱은 후속 단계로 두되, 동일한 로컬 검색 API를 재사용할 수 있게 설계한다.
- 초기 입력 형식은 `.mp4`만 지원한다.
- 검색 질의 입력은 한국어·영어·일본어 자연어 텍스트만 지원한다.
- 앱 UI, 설정, 진행 상태, 알림과 오류 메시지는 초기 버전에서 한국어만 제공한다.
- 영상 속 원문, OCR 원문과 사용자가 수정한 화자 이름은 UI 언어와 무관하게 원래 값을 유지한다.
- 앱의 작업명은 `영상찾기`이며 추후 표시 이름을 바꿔도 기존 데이터 위치와 색인 식별자는 유지한다.

| 파일명 | `31784_20260609-dc91f63eb6037f85 (1).mp4` |

| 파일 크기 | 378,816,659 bytes, 약 361MiB |

이 파일을 하네스의 기준 영상으로 사용한다. 문서와 설정에는 절대 경로를 기본값으로 고정하지 않고, 실행 시 파일 경로를 전달한다. 원본 파일의 해시를 기록해 같은 영상으로 실험했는지 확인한다.

## 4. 해결하려는 문제

긴 영상에서 원하는 내용을 찾으려면 사용자가 재생 위치를 직접 옮기며 확인해야 한다. 특히 다음 두 경우는 일반적인 자막 검색만으로 해결하기 어렵다.

1. 영상의 표현과 사용자의 검색 표현이 다른 경우
2. 말로 설명되지 않고 화면에만 등장하는 사물·행동·문자를 찾는 경우

예를 들어 영상에서 “배포 날짜를 다음 주로 미루겠습니다”라고 말했을 때 사용자가 “출시 연기를 제안한 부분”이라고 검색해도 해당 장면을 찾아야 한다. 또한 “빨간 자동차가 터널로 들어가는 장면”처럼 화면 자체에 대한 질의도 처리해야 한다.

## 5. 제품 목표

### 핵심 목표

1. 자연어로 영상의 발화 내용을 검색한다.
2. 자연어로 영상의 화면 장면을 검색한다.
3. 검색 결과에 타임코드와 검색 근거를 표시한다.
4. 결과를 선택하면 해당 시점부터 영상을 재생한다.
5. 모든 분석과 검색을 로컬에서 수행한다.
6. 평가 하네스로 모델과 설정의 품질을 반복 비교한다.
7. 한국어·영어·일본어 및 서로 다른 질의·발화 언어 조합을 검색한다.

### 비목표

- 여러 영상에 대한 통합 검색
- MOV·MKV·WebM 등 MP4 이외의 입력 형식
- 실시간 스트리밍 분석
- 다중 사용자와 권한 관리
- 얼굴을 실명으로 식별하는 기능
- 클라우드 배포와 모바일 앱
- 다른 Mac에 배포하기 위한 서명·공증·자동 업데이트
- Intel Mac 지원과 범용 바이너리
- 초기 버전의 네이티브 macOS UI
- 참조 이미지 업로드를 이용한 유사 장면 검색
- 음성으로 검색어 입력
- 영어·일본어 UI 및 화면 언어 전환
- 검색 결과의 맞음·아님 피드백 수집
- 영상 편집 및 자동 하이라이트 제작
- 생성형 AI 기반 영상 질의응답

## 6. 목표 사용자

초기 사용자는 이 Mac의 소유자 한 명이다.

대표 사용 상황:

- 강의에서 특정 개념을 설명한 부분 찾기
- 회의 녹화에서 특정 제안이나 결론 찾기
- 촬영 영상에서 특정 사물이나 행동이 등장하는 장면 찾기
- 화면에 특정 문구나 슬라이드가 등장하는 시점 찾기

## 7. 검색 범위

### 7.1 발화 검색

영상의 음성을 타임코드 자막으로 변환하고 의미 임베딩을 생성한다.

예시:

```text
검색: 비용을 낮추는 방법을 설명한 부분
결과: 00:18:42
근거: “서버를 계속 켜두지 않고 요청이 있을 때만 실행하면…”
```

### 7.2 화면 검색

영상에서 대표 프레임을 추출하고 이미지 임베딩을 생성한다.

예시:

```text
검색: 빨간 자동차가 터널에 들어가는 장면
결과: 00:32:15
근거: 해당 시점의 대표 프레임
```

### 7.3 화면 문자 검색

대표 프레임에서 OCR로 문자를 추출한다. 슬라이드 제목, 간판, 자막처럼 화면에 표시된 정확한 문구를 검색할 때 사용한다.

예시:

```text
검색: Create Vector Index가 적힌 화면
결과: 00:07:21
근거: OCR “CREATE VECTOR INDEX”
```

### 7.4 통합 검색

발화, 화면, OCR 검색 결과를 시간축에서 결합한다. 하나의 시점에서 여러 신호가 일치하면 결과 순위를 높인다.

### 7.5 다국어 결과 표시

- 자막 근거는 영상에서 인식한 원문을 항상 보존한다.
- 원문이 검색어 언어와 다르면 검색어 언어로 번역한 문장을 함께 표시한다.
- 번역문은 이해를 돕는 보조 정보이며 검색 근거의 원본을 대체하지 않는다.
- 번역은 외부 API가 아닌 로컬 모델로 생성한다.

- 초기 색인 시간을 줄이기 위해 번역은 검색 결과에 노출된 구간부터 생성하고 캐시한다.

### 7.6 선택적 화자 구분

- 영상 분석 전에 `화자 구분`을 켜거나 끌 수 있다.
- 끄면 모든 발화를 화자 정보 없이 검색한다.
- 켜면 발화를 `Speaker 1`, `Speaker 2`처럼 구분한다.
- 검색 결과에 화자 라벨을 표시하고 특정 화자만 필터링할 수 있다.
- 사용자는 자동 생성된 화자 라벨을 원하는 이름으로 수정할 수 있다.
- 수정된 이름은 해당 영상에 저장되고 검색 결과와 필터에 반영된다.
- 화자 구분 실패가 발화 검색 전체를 막아서는 안 된다.
- 얼굴을 실제 사람의 이름으로 자동 식별하는 기능은 포함하지 않는다.

## 8. 핵심 사용자 흐름

### 8.1 영상 분석

1. 사용자가 영상 파일을 선택한다.
2. 앱이 예상 처리 시간과 필요한 저장 공간을 안내한다.
3. 사용자가 분석을 시작한다.
4. 앱이 `빠른 색인`과 `추가 분석`의 단계별 진행률을 표시한다.
5. 빠른 색인이 완료되면 검색을 활성화한다.
6. OCR·화자 구분 등 추가 분석은 백그라운드에서 계속하며 완료된 채널부터 결과에 반영한다.
7. 장시간 영상은 현재 분석 완료 범위와 전체 진행률을 시간축으로 표시한다.

동일한 영상이 이미 등록되어 있으면 다음 선택지를 표시한다.

- `기존 분석 결과 열기` — 재분석 없이 기존 색인을 활성화한다.
- `새 버전으로 다시 분석` — 같은 영상 레코드에 새 색인 버전을 만든다.
- `취소` — 아무 변경 없이 파일 선택 화면으로 돌아간다.

기본 선택은 `기존 분석 결과 열기`로 한다. 재분석하더라도 영상 목록에 동일 영상을 별도 항목으로 중복 생성하지 않는다.

### 8.2 영상 검색

1. 사용자가 검색어를 입력한다.
2. `통합`, `발화`, `화면` 중 검색 모드를 선택한다.
3. 앱이 관련도순으로 최대 5개의 결과를 표시한다.
4. 모든 후보가 신뢰도 기준보다 낮으면 `관련 결과 없음`을 표시한다.
5. 사용자가 결과의 썸네일, 타임코드, 자막 또는 OCR 근거를 확인한다.
6. 결과를 선택하면 영상이 해당 시점부터 재생된다.

### 8.3 품질 평가

1. Claude가 기준 영상을 직접 탐색하고 재생해 질의와 정답 타임코드를 평가 데이터에 기록한다.
2. 평가 하네스가 동일 질의를 현재 색인에 실행한다.
3. Recall@K, MRR@K, 타임코드 오차와 처리 시간을 기록한다.
4. 모델 또는 설정 변경 전후 결과를 비교한다.

평가 세트는 검색 모델을 실행하기 전에 초안을 만들고, 각 정답을 원본 영상 재생으로 검증해 고정한다. 평가 대상 검색 시스템이 낸 후보를 검증 없이 정답으로 복사해서는 안 된다. Claude가 작성·검증·버전 관리를 모두 담당하며 사용자에게 질의 작성이나 타임코드 라벨링을 요구하지 않는다.

### 버전 및 용량 정책

- SHA-256이 같은 원본은 하나의 `video_id`로 관리한다.
- 해당 `video_id`의 공통 파생 데이터와 모든 `index_version` 데이터의 합계가 2GB를 넘지 않아야 한다.
- 여러 버전에서 같은 프레임·오디오 중간 산출물을 사용할 수 있으면 한 번만 저장하고 공유한다.
- 재분석 전에 현재 사용량, 새 버전의 예상 추가 용량, 재분석 후 예상 합계를 표시한다.
- 2GB 초과가 예상되면 분석을 바로 시작하지 않고, 사용자가 오래된 버전 정리 또는 취소를 선택하게 한다.
- 앱은 오래된 버전이나 원본 영상을 자동으로 삭제하지 않는다.
- 오래된 버전의 대용량 프레임·임베딩을 정리하더라도 설정, 모델 revision, 평가 점수, 처리 시간 등 작은 실험 기록은 보존한다.
- 공유 데이터는 이를 참조하는 버전이 하나라도 남아 있으면 삭제하지 않는다.

## 11. 검색 결과 정의

각 결과는 다음 정보를 제공한다.

| 필드 | 설명 |
|---|---|
| 시작·종료 시간 | 재생할 영상 구간 |
| 상대 관련도 | 현재 결과 집합 안에서 보정한 점수 |
| 검색 채널 | 발화, 화면, OCR 또는 조합 |
| 자막 근거 | 발화 검색에 기여한 문장 |
| 번역문 | 원문과 질의 언어가 다를 때 표시하는 로컬 번역 결과 |
| 화자 | 화자 구분을 사용했을 때의 Speaker 라벨 |
| OCR 근거 | 화면 문자 검색에 기여한 문구 |
| 대표 프레임 | 화면 검색에 기여한 이미지 |

모델의 원시 cosine 점수를 정확도처럼 표시하지 않는다. 사용자에게는 결과 간 상대적 관련도만 제공한다.

## 12. 비기능 요구사항

### 개인정보 보호

- 원본과 파생 데이터는 로컬 디스크에만 저장한다.
- 외부 분석 API를 호출하지 않는다.
- 영상·오디오·프레임·자막을 제3자 서버에 업로드하지 않는다.
- 최초 모델 다운로드 이외의 네트워크 통신 없이 동작할 수 있어야 한다.
- 모델 다운로드 전에 모델별 이름·용도·용량·라이선스 등급과 전체 필요 공간을 표시해야 한다.
- 모델 파일은 임시 경로에 내려받아 무결성 검증이 끝난 뒤 모델 캐시로 원자적으로 이동해야 한다.
- 사용자가 분석 결과와 모델 캐시의 위치를 확인할 수 있어야 한다.
- 사용자가 영상별 파생 데이터와 색인을 직접 삭제할 수 있어야 한다.
- 모델 캐시와 영상별 색인 사용량을 분리해 표시해야 한다.
- 영상별 사용량은 공통 데이터, 활성 버전, 이전 버전으로 나눠 표시해야 한다.

### 라이선스 정책

- 이 버전은 개인 실험용이므로 상업 이용 가능 라이선스만을 절대 조건으로 삼지는 않는다.
- 기본 추천과 최종 채택은 가능하면 상업 이용 가능한 라이선스를 우선한다.
- 코드 라이브러리 라이선스와 모델 가중치 라이선스는 별개로 확인한다.
- 채택 항목마다 이름, 버전 또는 revision, 출처, 라이선스, 상업 이용 가능 여부, 재배포 조건을 기록한다.
- `non-commercial`, `research only`, 용도 제한, 사용자 수 제한 또는 별도 동의가 필요한 항목은 `개인 실험 전용`으로 표시한다.
- 개인 실험 전용 모델에 의존한 색인은 향후 모델 교체와 재색인이 가능하도록 구현을 분리한다.
- 라이선스가 불명확한 모델은 기본 설정으로 채택하지 않는다.

### 성능

- 약 1시간 영상의 빠른 색인은 5분 이내 완료를 목표로 한다.
- 빠른 색인은 발화 의미 검색과 기본 화면 검색을 포함한다.
- 추가 분석이 진행 중이어도 완료된 채널로 검색할 수 있어야 한다.
- 최대 10시간 영상을 입력할 수 있어야 한다.
- 10시간 영상은 5분 이내 완료된 구간부터 검색을 시작한다.
- 10시간 영상 전체의 발화 및 기본 화면 검색 범위는 1시간 이내 확보를 목표로 한다.
- 전체 범위 완료 전 검색 결과에는 `분석된 범위 내 결과`임을 표시한다.
- 분석 이후 검색 결과는 2초 이내 표시를 목표로 한다.
- 검색 앱은 16GB 메모리 환경에서 안정적으로 실행되어야 한다.
- 색인 과정에서 대형 모델을 동시에 여러 개 메모리에 올리지 않는다.
- 앱을 다시 실행해도 기존 색인을 재사용한다.

### 안정성

- 분석 실패 시 원본 영상을 변경하거나 삭제하지 않는다.
- 일부 채널이 실패하더라도 생성된 다른 채널로 검색할 수 있다.
- 중간 결과와 완료된 색인을 구분한다.
- 모델과 색인 버전이 맞지 않으면 재색인을 안내한다.
- 장시간 분석 중에는 macOS 절전 방지를 요청하고 작업 종료·중지 시 반드시 해제한다.
- 분석 중 앱 종료를 선택하면 경고하고, 확인 시 checkpoint 저장과 작업 정리 후 백엔드를 종료한다.

## 13. 성공 기준

### 제품 완료 기준

- 실제 영상 한 개를 처음부터 끝까지 로컬에서 분석할 수 있다.
- 서로 다른 표현을 사용한 발화 질의로 관련 구간을 찾을 수 있다.
- 사물 또는 행동에 대한 화면 질의로 관련 프레임을 찾을 수 있다.
- 화면에 표시된 문자를 검색할 수 있다.
- 검색 결과를 선택하면 해당 타임코드부터 재생된다.
- 앱 종료 후 재실행해도 기존 색인을 사용할 수 있다.
- 분석했던 영상을 다시 선택하면 재분석 없이 검색할 수 있다.
- 터미널을 열지 않고 앱 아이콘만으로 서버와 웹 UI를 시작할 수 있다.

### 품질 목표

Claude가 최소 30개의 실제 질의를 발화·화면·OCR·결과 없음 범주로 나눠 평가한다. 개발용 20개와 최종 확인용 holdout 10개 이상으로 분리하고, holdout 결과를 본 뒤 임계값이나 가중치를 다시 조정하지 않는다.

| 지표 | MVP 목표 |
|---|---:|
| Recall@5 | 80% 이상 |
| MRR@5 | 0.65 이상 |
| 타임코드 시작 오차 | 평가 정답 기준 3초 이하 |
| 검색 응답 시간 | 2초 이하 |
| 영상 분석 성공률 | 대상 영상에서 100% |
| No-result precision | 80% 이상 |

질의 수가 적으므로 수치는 제품 성능의 절대적인 보증이 아니라 설정 비교를 위한 기준으로 사용한다.

## 16. 확정된 결정

- 한 번에 검색하는 활성 영상은 한 개이며, 이전 영상과 색인 버전은 로컬 라이브러리에 보관한다.
- 로컬 AI만 사용한다.
- 발화 검색과 화면 검색을 모두 제공한다.
- 화면 문자 검색을 포함한다.
- 데이터베이스 서버 없이 로컬 파일 색인으로 시작한다.
- UI보다 검색 품질을 먼저 검증하는 하네스 중심 개발을 적용한다.
- 동일 영상의 모든 분석 버전과 공통 파생 데이터 합계를 2GB로 제한하며 자동 삭제하지 않는다.
- 첫 사용자 실행 방식은 로컬 `.app` 아이콘 더블클릭이며, 전체 네이티브 UI는 후속 범위다.
- 백그라운드 실행 상태와 종료 제어는 macOS 메뉴 막대 아이콘에서 제공한다.
- 최초 실행 시 모델 다운로드를 한 번 확인받고 자동 설치하며, 중단되면 다음 실행에서 이어받는다.
- 첫 앱 번들은 Apple Silicon 전용이며 FFmpeg·Python·필수 패키지를 자체 포함한다.
- 초기 UI 언어는 한국어로 고정하며 영어·일본어는 검색 대상 언어로만 지원한다.
- 초기 앱 표시 이름은 `영상찾기`다.
